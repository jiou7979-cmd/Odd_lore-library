# 이변록 도서관

스마트폰 우선의 정적 기록 아카이브. HTML/CSS/JavaScript만 사용하며 빌드 도구나 서버가 필요 없습니다.

## GitHub Pages 배포

1. GitHub에서 새 저장소 `ibyeonrok-library`를 만듭니다.
2. 저장소 공개 범위는 **Public**으로 설정합니다. GitHub Free에서 Pages를 사용할 때 공개 저장소가 필요할 수 있습니다.
3. 이 ZIP 안의 파일을 저장소 최상위(root)에 업로드합니다. `index.html`, `style.css`, `records.js`, `app.js`, `.nojekyll`이 최상위에 있어야 합니다.
4. 저장소의 **Settings → Pages**로 이동합니다.
5. **Build and deployment → Deploy from a branch**를 선택합니다.
6. Branch는 `main`, 폴더는 `/(root)`로 선택하고 Save를 누릅니다.
7. 배포가 끝나면 Settings → Pages에 표시되는 사이트 주소로 접속합니다. 첫 배포에는 시간이 걸릴 수 있습니다.

## 기록 추가·수정

`records.js` 파일을 열고 `window.ARCHIVE_RECORDS` 배열 안에 기록 객체를 추가하거나 기존 예시를 수정합니다.

```js
{
  id: "CHR-002",
  type: "character",
  title: "캐릭터 이름",
  subtitle: "짧은 부제",
  summary: "목록에 표시될 소개",
  body: "상세 설정\\n성격과 관계 등을 여기에 작성",
  tags: ["태그1", "태그2"],
  date: "2026-10-24"
}
```

- `type`: 인물은 `character`, 플롯은 `plot`
- `id`: 각 기록마다 고유하게 지정
- `body`: `\\n`을 사용하면 상세 보기에서 줄바꿈됩니다.
- 저장하면 GitHub Pages가 사이트를 다시 배포합니다.

## 권한 및 개인정보 주의

이 사이트는 정적 사이트입니다. 방문자는 사이트를 열람하고 검색할 수 있지만, 사이트 화면에서 기록을 직접 추가하거나 수정하는 기능은 없습니다. 관리자는 GitHub 저장소의 권한으로 파일을 수정합니다.

**중요:** 공개 저장소에 올라간 `records.js` 및 사이트 파일은 방문자가 확인할 수 있습니다. 정적 사이트 안에 비밀번호를 넣거나 관리자 비밀번호 입력창으로 기록을 보호하는 방식은 안전한 접근 제어가 아닙니다. 공개하면 안 되는 개인 정보나 비공개 초안은 올리지 마세요. 진짜 비공개 기록·로그인 기능이 필요해지면 인증과 데이터베이스를 지원하는 별도 백엔드가 필요합니다.

## 포함된 기능

- 모바일 반응형 디자인
- 인물/플롯 분류 필터
- 제목·태그·상세 내용 검색
- 기록 상세 팝업
- 기록 수 자동 집계
- 외부 라이브러리 없이 작동
